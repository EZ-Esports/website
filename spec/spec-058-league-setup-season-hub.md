# spec-058: League Setup season hub (per-game tabs, season page)

- **Status:** Implemented on branch `worktree-agent-a1034cb896548c04e`; no migration; not run against any database; not viewed in a browser.
- **Date:** 2026-11-04
- **Scope:** `app/(admin)/admin/league/` (`page.tsx`, `LeagueSetupClient.tsx`, new `[seasonId]/`, new `season-schools-actions.ts`), `app/lib/season-schools.ts`, `app/lib/db/season-setup.ts`, `app/lib/admin-season-filters.ts`, `app/lib/admin-nav.ts`, `SchoolManagersModal` + `ProvisionInviteTab`, `matches/page.tsx` (back link only).

## Context

League moderation was spread over League Setup (lock / publish buttons on every season row), Schools & Rosters (teams and rosters), the school managers dialog (invite links) and Matches. Staff had to remember which page held which switch, and school managers had to create their own Varsity / JV rosters.

## Design decisions

- **Per-game tabs.** League Setup is one `AdminFilterTabs` strip, one tab per game (`?game=<slug>`, unknown or missing falls back to the first game) plus **Manage games** (`?view=games`), which holds the former Games section (add, edit, delete). Inside a game the seasons list keeps spec-025's Active / Inactive / All filter, now counted per game, and the add-season form has the game preselected. `resolveLeagueView`, `leagueHref`, `seasonDetailHref` are pure helpers in `admin-season-filters.ts`; the "season moved tab" hint and the Matches back arrow keep the game.
- **Season rows are navigation, not controls.** The name and an "Open season" chip open `/admin/league/[seasonId]`. Lock and publish are no longer buttons on rows; their state stays visible as chips. Edit and delete stay on the row. "View matches" moved into the season page.
- **Season page** (`/admin/league/[seasonId]`, gated on `MANAGE_LEAGUE` like League Setup, breadcrumb title "Season", back arrow to the season's game tab and status filter):
  - *Season controls:* Lock / unlock rosters and Publish / unpublish, same server actions and confirm dialogs as before (`lockSeasonRosters`, `publishSeasonOutcomes`, ...), unchanged.
  - *Schools:* a responsive grid of tiles (1 / 2 / 3 columns), one per school with a team in the season: crest (`SchoolCrest`, the logo Schools & Rosters shows, or the school's initials), name, "N rosters · M players", a chip per roster and a warning chip per missing division (`getSeasonSetupData`, raw and uncached). The name is a stretched link over the whole tile to the school's season page; **Managers** and **Create missing rosters** sit above that overlay so they stay separately clickable.
  - *School in season* (`/admin/league/[seasonId]/schools/[schoolId]?game=`): gated on `MANAGE_LEAGUE`; UUID-validated (`notFound` on a malformed id or a school with no team in the season); params awaited. Header with crest, roster and player counts, missing-division and locked chips, and a back link to the season page. There is no link out to Schools & Rosters: rosters are edited here. For staff who also hold `MANAGE_ROSTERS` (the permission Schools & Rosters requires) the body is the existing `SchoolRostersView` in `scope="season"`, fully editable with the same controls and server actions (which keep their own `MANAGE_ROSTERS` and school-scope checks). Season-only by construction: `getSchoolRosterBlocks(schoolId, { seasonId })` filters the team query itself (a season belongs to one game, so no other game's team, roster or player is read), `getRosterEditOptions(schoolId, { seasonId })` reads only this season, its one game and the school's members, the page additionally drops any block whose season or game differs from the season's, and `?game=` on the URL is never consulted. The scope drops only the cross-game and cross-season chrome (game filter, season accordion header, Register team panel); every roster and player field, badge and control stays. Shown: roster name, division, N/10 players, per player IGN or name, role badge, real name, Discord, class of, **school email and personal email** (`members.school_email` and `members.email`, each labelled, "not on file" when missing; the same rendering in Schools & Rosters), "View student ID" signed-URL link, content-flag badges with their review controls, the Varsity/JV columns with placeholders and the division filter, and the locked note. Without `MANAGE_ROSTERS` none of that is queried: staff see only roster names and player names with roles. Roster-editor writes now also revalidate `/admin/league` (layout) so the season pages follow.
  - *Add school:* a picker of live (not soft-deleted) schools without a team in this season, and **Add school**.
  - *Manager invites:* per school, opens the existing `SchoolManagersModal` with `seasonName` set, so the Provision tab issues the link for this season (`academicYear` = season name, fixed and not editable) through the unchanged `generateManagerInvite` / `manager_invites` flow (14-day single-use token, revoke list). Drawn only for staff holding `MANAGE_SCHOOLS` (the action checks again) and only when the season name is `YYYY-YY`. Game scope stays "All games" by default, as before.
  - *Edit rosters:* link to the school's existing roster editor (`/admin/schools/[id]/rosters?game=`), shown with `MANAGE_ROSTERS`.
- **Add school to season** (`addSchoolToSeason`, `season-schools-actions.ts`, `MANAGE_LEAGUE`, zod-validated ids). One transaction: season + game, school (not soft-deleted), a per-(season, school) advisory lock, find-or-create the `teams` row (unique school + game + season), then create the rosters `planSchoolRosters` says are missing. Same shape the manager portal and Generate season write: team per (school, game, season), rosters named `Varsity` / `JV`, stored `A` / `B` (`storedDivision`).
- **Which rosters.** The divisions the game allows (`allowedRosterDivisions`): Varsity + JV for Valorant and League of Legends, Varsity only for Minecraft, a single `All` roster for the tournament games (TFT, osu!, TETR.IO). A division that already has a roster under any name or stored spelling (`A` / `Varsity`) counts as present, so a manager-built roster is never duplicated; a name collision on another division gets `Varsity 2`, mirroring Generate season. This is the idempotency rule: calling the action again creates nothing, and on a team missing only JV it adds only JV.
- **Scope is one game and one season (confirmed).** Adding a school to Valorant 2026-27 creates only Valorant's rosters for 2026-27; the page copy and toasts say "the rosters this game fields" and name them ("Varsity and JV rosters" / "Varsity roster"; `rosterNamesPhrase`), never a blanket "Varsity and JV".
- **Managers per school (follow-up).** The per-school **Managers** button opens the reused dialog with the Provision tab pinned to this season. New invites keep the "All games" default; a manager made from a game's page is NOT scoped to that game. The dialog previously could not edit an existing manager's scope (only remove, or re-assign through the Assign tab), so the Active managers tab now has an **Edit access** control per manager: all games or specific games (every game is offered, not just this one) and the primary-contact flag. It calls `updateSchoolManagerAccess` (`MANAGE_SCHOOLS`, game slugs validated against `games`, empty selection rejected, removed managers refused so the upsert cannot reactivate them, audit-logged as `update_school_manager_access` with before/after, `schools` and `teams` tags updated). The write is `updateActiveSchoolManagerAccess` (`onboarding-repository.ts`): one transaction whose UPDATE carries `is_active = true` in its WHERE, so a removal racing the edit wins and the call returns null (the assignment upsert is not used, because it forces `is_active` back on). Promoting to primary demotes the other managers of the same school and year in that transaction, after the target is confirmed active; a lost race rolls the demotion back. Covered by a PGlite test. Each manager row is a React Aria `Disclosure` (controlled by one `editingId`, so Save and Cancel close it): RAC owns `aria-expanded` / `aria-controls` and labels the panel from the Edit access trigger; there is no hand-written focus code. Known limit: a save reloads the list, which remounts the row, so focus falls back to the document rather than the trigger. The dialog's banners are `AdminNotice`s, i.e. `role="status"` / `role="alert"`.
- **Refresh after season-page writes.** `revalidateLeague` now revalidates `/admin/league` with `'layout'`, which covers `/admin/league/[seasonId]`, so header chips follow Lock / Unlock / Publish. The roster editor already honored `?game=` (the page validates it against the school's teams; unit-tested).
- **Races.** The advisory lock serializes two staff adding the same school; the unique indexes (`teams_school_game_season_unique_idx`, `rosters_team_name_unique_idx`) remain the backstop, and a 23505 maps to a "refresh and check" message.
- **Staff, not managers, so the season lock does not apply** (spec-020): a locked season can still be populated.
- **Cache.** Tags `teams`, `rosters` are updated, plus `revalidatePath` for the season page, `/admin/schools` (layout), `/admin/matches`, `/portal`, `/`. Nothing is refreshed when nothing was created.
- **Consolidation.** Nothing was removed. League Setup's nav description names the new scope; Schools & Rosters keeps school CRUD, crests, and the all-seasons roster editor (linked from each school here); Matches keeps scheduling, results and Generate season (linked via "View matches"); Onboarding Form and Standings Archive are untouched.

## Remove a school from a season (migration 0059, NOT applied)

**Why a column.** `teams` and `rosters` have no hidden/deleted/active flag, and `schools.is_active` / `deleted_at` are school-wide, not per game and season. Deleting the team row is not an option: `rosters.team_id` and `players.roster_id` are `ON DELETE CASCADE`, so it would destroy the rosters and players, and matches hang off rosters. Encoding it in roster names or another table was rejected as a hack that every query would still have to learn. So `teams.removed_at timestamp NULL` (`db/migrations/0059_team_removed_at.sql`, journal idx 59, additive, no backfill). Roster editing, parity and the emails need no migration.

**What removal does.** `removeSchoolFromSeason` (`MANAGE_LEAGUE`, confirm dialog, audit `remove_school_from_season`) sets `removed_at` under the same per-school advisory lock; it is idempotent. The team row, its rosters, players and every match stay in the database untouched. Staff views (Schools & Rosters, Matches, the staff match list) still see everything.

**What disappears.** Season page school list and the "already added" set (the school returns to the Add school picker, labelled as removed earlier); public team directory, school team page, team list cache, computed standings rows, the schedule form's roster list; and every public match read that already hid fixtures of a soft-deleted school now also skips a removed team (public match list and counts, season calendar, school fixtures, recent results, hub next/last and form guide), so fixtures and results involving a removed school are hidden from the public. The school's manager no longer sees its rosters, and manager roster creation refuses it. Generate season and staff Schedule match refuse a removed school until it is added back.

**Restore.** Add school on a removed school clears `removed_at` on the same team: its existing rosters, players and matches come back; only a missing division gets a new roster; no second team is created.

**Known limits.** Derived (non-snapshot) standings for the removed school's opponents still count their results against it, because they come from the `roster_standings` view over matches; changing that needs a view migration, not done. The archive's per-season match count still counts all matches. Public pages cached with `revalidatePath`/tags are refreshed on removal and restore.

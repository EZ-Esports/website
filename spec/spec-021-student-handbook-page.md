# Spec-021: Student Handbook page

**Branch:** `worktree-student-handbook-page`. **PR:** not opened. **Status:** Code ready. No migration. Needs the existing `admin-uploads` bucket and `NEXT_PUBLIC_SUPABASE_URL` (both already live for gallery images).

## Context & Motivation

Leadership publishes a yearly Student Handbook (key links, games, the three communities, the season timeline, the #1 rule) as a Google Doc and an interactive HTML pamphlet (a page-by-page viewer). Students had no page on the site for it. Staff edit the doc and export a PDF, so the site needs a public page that shows that PDF and a way for staff to swap it without a deploy.

## Design Decisions

- **Route `/handbook`**, a normal marketing page (site nav and footer unchanged, no Hero). Linked from the **footer only** (`FOOTER_LINKS`, "Student Handbook"); top nav unchanged. In `ROUTES` and the sitemap. Title is the bare "Student Handbook" (the layout template adds the site name). `export const revalidate = 60` so a DB failure (which renders the bundled pages) heals within a minute instead of freezing until a deploy.
- **Pamphlet-style viewer** (`app/components/handbook/HandbookViewer.tsx`, client): sidebar with a "Having trouble viewing? Open in Google Docs" button, chapter list, search with per-page results; toolbar with page counter, Prev/Next, zoom (continuous, 1x to 4x of the fit scale, driven by trackpad pinch or Ctrl+scroll while the cursor is over the pages: the wheel listener is non-passive and only handles `ctrlKey` wheel events, so plain scrolling still scrolls the page and browser zoom elsewhere is untouched; Safari uses gesture events; the point under the cursor stays fixed; `+`/`-`/`0` keys for keyboard users; a Reset button appears once zoomed; the opening view is 110% of the exact fit (`DEFAULT_ZOOM` = 1.1, the whole page or both pages of a spread; phones open at exactly the width), pinching out reaches 1x. No menu or buttons; labelled Fit width on phones) and a "Read as text" toggle; **an open-book two-page spread** on tablets and desktops (cover alone, then pairs 2-3, 4-5, ...; an odd last page alone; see Spreads below) or one page at a time on phones, growing with zoom (the page scrolls vertically with the document; a zoomed spread scrolls sideways inside the panel); page-number dots; mobile "Contents & search" toggle; print styles. Styled with site tokens. The panel behind the page is **light** (`VIEWER_BACKDROP`, `bg-[#e9e6e6]`, a single constant to change) with the white page separated by shadow and ring. Pure logic is in `app/lib/handbook-viewer.ts` and tested.
- **Spreads:** `canShowSpread` (viewport wider than `NARROW_MAX_WIDTH` and a viewer box of at least `SPREAD_MIN_BOX_WIDTH` = 560 px, so each page is about 280 px or more) turns on two-page mode, otherwise (phones, narrow tablet boxes) one page at a time. Pure helpers `spreadStart` / `spreadSize` / `previousSpreadStart` () map any page index to its spread; `current` stays a raw page index and the spread is derived, so a resize between modes never loses the place. Prev/Next, arrow keys, swipe, dots, chapter list, search hits and link boxes all go through `go()`, which snaps to the spread. The spread is one animated wrapper holding both pages (2 px gutter, each page with its own link boxes). Full page fits the whole spread (both pages) in the viewer box (`fitSheetWidth` with `count` = pages shown); zoom in/out scales that. Counter reads `Pages 2–3 / 7`, the live region `Pages 2 and 3 of 7`; the dots and chapter list highlight every page in view.
- **Navigation:** left/right arrow keys; tap/click the outer 15% of the whole spread (left/right edges) (aria-hidden, under the link boxes so links still win; no text layer to select); horizontal swipe on touch (quick, mostly sideways, single finger, ignored while pinch-zoomed or horizontally scrollable). The counter, Prev/Next, zoom and text toggle sit in a `sticky top-[88px]` bar under the site nav.
- **URL hash:** the current page is `#page-N`. Read on load (and again when a PDF's page count is known), written with `replaceState` on navigation (the first page of the spread; a hash naming the second page of a spread shows that spread) (one history entry per page turn would bury Back), and followed on `hashchange`. Sheets use ids `handbook-page-N` so the browser does not scroll-jump to the hash. Internal link boxes route through the same navigation.
- **Phones:** viewports 767 px and narrower show one page, fitted to the width (the 'Full page' option reads "Fit width"); larger screens fit the whole page or spread on screen. No `touch-action` override, so pinch-zoom works.
- **Accessibility:** "Skip to the handbook" link; a polite live region announces "Page N of M" (or "Pages N and M of T" for a spread) on page change (the visible counter is not live); "Read as text" is an `aria-pressed` toggle that moves focus into the text article; animations are `motion-safe`, smooth scrolling is skipped under `prefers-reduced-motion`.
- **Read as text:** headings, paragraphs and lists rebuilt from the extracted text (`structureHandbookText`: known section headings, bullet glyphs, page numbers) with the pamphlet's link labels linkified (`linkifyText`, safe schemes only). Bundled pages use `BUNDLED_TEXT_HEADINGS`; a PDF uses its outline titles as headings. The extraction has no layout, so unbulleted runs (e.g. the Key Links list) read as one paragraph.
- **Two page sources, one viewer.**
  - **Staff PDF uploaded:** rendered in the browser with **pdf.js** (`pdfjs-dist` 6.3.289, dynamically imported by `app/lib/handbook-pdf.ts`, same-origin worker emitted by the bundler). Each page is a canvas; Link annotations become overlay boxes (http/https/mailto plus in-document jumps); `getTextContent` feeds search; the PDF outline, when present, becomes the chapter list.
  - **No PDF, DB read failure, or pdf.js failure:** the bundled pamphlet pages. The seven designed pages are JPEGs under `public/handbook/` (1224 px wide, about 1.2 MB total), with the pamphlet's link boxes, extracted text and chapter list in `app/lib/handbook-pages.ts`. When an uploaded PDF fails to load a notice explains and links to "Open the PDF directly".
  - The earlier iframe viewer was removed: the site's `frame-ancestors 'none'` / `X-Frame-Options: DENY` blocks framing PDFs, so it rendered blank.
- **Open PDF / Download PDF** buttons appear only when a PDF exists. Download adds Supabase's `?download=<filename>` so it saves instead of navigating.
- **CSP:** pdf.js fetches the PDF from Supabase under the existing `connect-src https://*.supabase.co`. Added `worker-src 'self' blob:` (explicit, because `strict-dynamic` makes the `script-src` fallback unreliable for workers). `frame-src` is unchanged. Requires the Supabase public bucket to answer cross-origin GETs (it sends permissive CORS).
- **Link safety:** link targets from the pamphlet data and from PDF annotations are untrusted; only `http(s):` and `mailto:` render (`resolveHandbookLink`). http(s) open in a new tab with `noopener noreferrer`; mailto does not open a tab.
- **No schema change.** The PDF's storage key is one `page_content` row, key `handbook_pdf`, created by an upsert (`setHandbookPdfKey`). `/admin/content` filters that row out of the text-block list and `savePageContentWithHistory` refuses to edit it as free text.
- **Client-side compression.** A designed handbook export is tens of MB of raw RGB, far over the 4 MB cap, and the platform rejects large bodies before any route runs, so shrinking happens in the browser (`HandbookUploader.tsx` -> `handbook-compress-browser.ts`, lazy-loaded; `pdf-lib` 1.17.1). Staff may pick up to 50 MB; only files over 4 MB are touched. `handbook-compress.ts` (pure, injected IO, unit-tested in Node) re-encodes only large (>100 KB), Flate, 8-bit, RGB/gray (device or ICC), unmasked, un-remapped images as JPEG (pass 1: q75, 1280 px wide; pass 2 if still over: q55, 1000 px), undoing PNG row predictors; text, fonts and link annotations are untouched and an image is kept as-is if re-encoding would not shrink it. Inflate uses `DecompressionStream`, encoding uses canvas. A failure never blocks an upload that already fits; otherwise the message says the size reached. Status text ("Compressing 20.5 MB…" / "Compressed to 1.8 MB, uploading…") is a `role=status` live region. A real 20.5 MB / 7-page handbook became 1.8 MB in about 1 s in the browser and rendered correctly in pdf.js. The sync PNG-unfilter loop runs on the main thread (yielding between images), so the UI can pause briefly on very large images.
- **Upload flow mirrors gallery images.** `POST /api/handbook` (MANAGE_CONTENT, 10 per minute per IP, `%PDF-` magic bytes, PDF only, 4 MB cap, public `admin-uploads` bucket, key `handbook/<timestamp>.pdf`), then server action `saveHandbookPdf(storageKey)` (MANAGE_CONTENT) re-validates the key shape (`isHandbookStorageKey`), upserts the row, `updateTag('page-content')`, revalidates `/admin/content` and `/handbook`, and best-effort deletes the superseded object. A failed save leaves the old handbook live. 4 MB because the multipart request must fit Vercel's 4.5 MB body limit.

## Invariants & Boundaries

- Only keys matching `^handbook/\d{10,16}\.pdf$` are stored or rendered; the public URL is built server-side from project URL, bucket and key.
- The bundled pages are the 2026-27 edition as designed (images are the source of truth, including the pamphlet's wording under Game Regulations). They go stale each season; refresh by replacing `public/handbook/page-N.jpg` and `handbook-pages.ts`, or just upload a PDF.
- No "remove PDF" control (replace only). The stored file is capped at 4 MB; picks up to 50 MB are compressed first and refused if still over.
- pdf.js standard-font and CMap data are not bundled: a PDF that relies on non-embedded standard fonts may render with substitute fonts. Exports from Google Docs embed fonts.
- Non-goals: per-game handbooks (sent by email), versioned PDF history, server-side PDF rendering.

## Verification

- `npx tsc --noEmit`, `npm run lint`, `npx vitest run` (new/updated: `handbook.test.ts`, `handbook-viewer.test.ts`, `api/handbook/__tests__/route.test.ts`, `admin/content/__tests__/handbook-actions.test.ts`, `(marketing)/handbook/__tests__/page.test.tsx`, `csp.test.ts`).
- Spreads: viewed at 1280 px (2-3 spread from `#page-3`, ←/→ and edge click, zooming in scrolls sideways in the panel, Full page fits both pages) and 375 px (single page, Fit width default). Not exercised in a browser: an odd-page-count document (covered by unit tests), a PDF in spread mode.
- Dev server: `/handbook` renders the bundled pages (hash load, edge zones, synthetic swipes, text view, fit-width at 375 px); with a temporary local sample PDF the pdf.js path rendered canvas pages, a link overlay and per-page search; pointing at a missing file showed the failure notice and bundled pages. The temporary override and sample file were removed before commit.
- Not verified: a real upload through Supabase (CORS for pdf.js, `?download=` behavior) in production.
